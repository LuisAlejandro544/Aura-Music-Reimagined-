# README_AI — Mapa rápido de extensión con IA

Guía práctica para extender **Aura Music** de forma ordenada usando asistentes de código.

## Puntos de extensión principales

| Qué quieres añadir | Dónde empezar | Qué conectar |
| :--- | :--- | :--- |
| Nueva función nativa, DSP, efecto visual o capacidad JS en Rust | `android/rust/aura_core/src/` (`Cargo.toml` + módulo `.rs` como `crossfeed.rs`, `spatial_8d.rs`, `reverb.rs` o `delete_fx.rs` + `lib.rs` o `bin/aura_qjs.rs`) | Añadir `external fun` y wrapper en `AuraRustBridge.kt` (`:core:rust`); si se consume en `:feature:*`, definir interfaz o estado en `:core:model` (ej. `DeleteEffectFrameRenderer`, `AudioEffectsState`); si es audio en tiempo real, integrarlo en `EqualizerProcessor` (`equalizer.rs`) / `AudioEffectsProcessor` (`reverb.rs`) / `RustEqualizerAudioProcessor` (`:core:player`). |
| Mejora en descargas `yt-dlp`, formatos/calidades, servicio en segundo plano o auto-actualización PyPI | `aura_ytdlp.py`, `YtDlpAudioDownloader.kt` y `AuraDownloadForegroundService.kt` (`:core:downloader`) | Mantener `AuraDownloadHost` en `AuraApplication`, exponer estados/calidades en `DownloadState`, `DownloaderEngineStatus`, `AudioDownloadQuality` y `DownloadFormatHelper` (`:core:model`), persistir en `DownloaderPreferencesRepository` (`:core:database`), conectar en `AuraLibraryCoordinator.kt` / `AuraViewModel.kt` y mostrarlo en `DownloaderScreen.kt` (`:feature:downloader`). |
| Nuevo campo o tabla en base de datos | `AuraEntities.kt`, `AuraMigrations.kt` y `AuraDatabase.kt` (`:core:database`) | Incrementar `AuraMigrations.CURRENT_DATABASE_VERSION`, añadir `Migration(n, n+1)` en `ALL_MIGRATIONS` (nunca destructiva), exponer en `MusicRepository` y `AuraModels.kt`. |
| Nueva opción en Ajustes, carpeta del sistema, auriculares/AVRCP, Crossfade/Velocidad/Tono de voz, Temporizador, Ecualizador o Crossfeed/8D/Reverb/Slowed | `SettingsScreen.kt` (`:feature:settings`), `PlayerScreen.kt` / `SleepTimerBottomSheet.kt` (`:feature:player`), `EqualizerScreen.kt` (`:feature:equalizer`), `AudioEffectsScreen.kt` (`:feature:effects`), `AuraSystemStorageManager.kt` (`:core:importer`) y DataStore (`PlaybackPreferencesRepository`, `AudioEffectsPreferencesRepository`, `HeadphonePreferencesRepository`, `StoragePreferencesRepository`, `ThemePreferencesRepository` en `:core:database`) | Exponer `StateFlow` y setters en `AuraPlaybackCoordinator.kt` / `AuraAudioTuningCoordinator.kt` / `AuraLibraryCoordinator.kt` y `AuraViewModel.kt`; si afecta al proceso `:player`, sincronizarlo mediante `AuraPlaybackTuningProvider`, `AuraPlayerConfigStore` (`aura_player_config.json`) o `AuraPlayerIpc`. |
| Detección de salida de audio o botones multimedia (cable / Bluetooth AVRCP) | `AuraAudioOutputMonitor.kt`, `AuraPlaybackService.kt` (`AuraMediaSessionCallback` + `SessionControlForwardingPlayer`) y `AuraPlayerController.kt` (`:core:player`) + `HeadphonePreferences` / `HeadphoneRoutingHelper` (`:core:model`) | Conectar flujo `outputRoute` y `headphonePreferences` en `AuraApplication.kt`, `AuraAudioTuningCoordinator.kt` y `AuraViewModel.kt`; no pedir permisos Bluetooth extra mientras `AudioDeviceCallback` cubra la detección. |
| Nueva pantalla, subvista o receptor de Intents ("Abrir con") | Nuevo composable o módulo `:feature:*` (como `AudioEffectsScreen.kt`, `ArtistDetailScreen.kt`, `QueueScreen.kt` o `SettingsSystemFolderScreen`); chrome/launchers compartidos en `AuraAppChrome.kt`; intents en `AndroidManifest.xml` + `MainActivity.kt` | Registrar ruta en `AuraRoutes` dentro de `AuraAppRoot.kt` y ocultar `showBottomChrome` si es vista inmersiva; procesar URIs externas en `AudioImporter.importExternalAudioUri`. |
| Cola de reproducción, Crossfade, velocidad/tono de voz, temporizador, Crossfeed/8D/Reverb/Slowed, agrupación por artista o color dinámico | `PlaybackQueueHelper` / `PlaybackTuningHelper` / `SleepTimerHelper` / `AudioEffectsState` / `ArtistPlaylistBuilder` (`:core:model`), `AuraSleepTimerBridge.kt` / `AuraPlaybackService.kt` / `AuraPlayerController.kt` (`:core:player`), `PlayerScreen.kt` / `SleepTimerBottomSheet.kt` / `QueueScreen.kt` / `CoverDynamicTheme.kt` (`:feature:player`) y `AudioEffectsScreen.kt` (`:feature:effects`) | Exponer acciones en `AuraPlaybackCoordinator.kt` / `AuraViewModel.kt` y conectarlas en `LibraryScreen`, `PlaylistsScreen`, `ArtistDetailScreen`, `PlayerScreen` (menú de 3 puntos), `QueueScreen` y `AudioEffectsScreen`. |
| Edición local de metadatos de pistas (título, artista o campos futuros) | `TrackMetadataHelper` (`:core:model`), `TrackDao.updateMetadata` / `MusicRepository.updateTrackMetadata` (`:core:database`) y `EditTrackMetadataDialog` (`AuraAppRoot.kt`) | Mantener la sincronización de `MediaItem` en `AuraPlayerController.syncMediaItemsMetadata` (`replaceMediaItem`), actualizar `aura_biblioteca.json` si la carpeta del sistema está activa y propagar `onEditMetadata` sin alterar el archivo de audio original. |

## Checklist antes de lanzar el Action `apk Debug`
1. Verifica que `tests/project-integrity.test.ts` pase al 100% (`npx --yes tsx --test tests/project-integrity.test.ts`).
2. Si agregaste un crate en `Cargo.toml`, confirma que su licencia sea MIT, Apache-2.0 o BSD y que compile para `armv7-linux-androideabi`, `aarch64-linux-android` y `x86_64-linux-android`.
3. Si tocaste `:core:downloader` o Chaquopy, mantén `version = "3.11"` para preservar compatibilidad con 32 bits (`armeabi-v7a`) y `extractPackages("yt_dlp_ejs")` para que `yt-dlp` encuentre los scripts EJS.
4. Si agregaste un módulo en `android/settings.gradle.kts`, confirma que tenga su `build.gradle.kts` y `minSdk = 26`.
5. Ejecuta manualmente el workflow **apk Debug** en la pestaña **Actions** de GitHub para obtener el APK compilado sin caché.
